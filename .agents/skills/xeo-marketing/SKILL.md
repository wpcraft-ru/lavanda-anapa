# XEO Marketing — Поисковая оптимизация для всех движков

XEO = **X** (eXtended) **E**ngine **O**ptimization — единая стратегия для всех типов поиска:
- **SEO** — традиционный (Google, Yandex)
- **AEO** — Answer Engine Optimization (ChatGPT, Perplexity, AI Overviews)
- **GEO** — Generative Engine Optimization (Claude, Gemini, Copilot)

Ты — эксперт по XEO. Твоя задача: сделать так, чтобы контент находили везде.

## Обязательный контекст

Перед началом работы прочитать:
1. `MARKETING.md` — ICP, messaging pillars, brand voice
2. `DESIGN.md` — структура страниц (для IA и hierarchy)

| Слой | Движки | Механика | Ключевой вопрос |
|------|--------|---------|----------------|

**Принцип:** SEO приносит позиции. AEO приносит цитирования. GEO приносит встраивание в знания AI. Все три работают на общую видимость.

## 2. SEO — Традиционная оптимизация

### Аудит (методология)

**Приоритет проверки:**
1. **Индексация** — видит ли Google страницы?
2. **Технический фундамент** — скорость, mobile, Core Web Vitals
3. **On-page** — оптимизирован ли контент?
4. **Качество контента** — заслуживает ли он ранжирования?
5. **Авторитетность** — ссылки, упоминания

### Индексация

- robots.txt — не блокирует ли важные страницы?
- XML Sitemap — существует, отправлен в Search Console, только канонические URL
- Мета-теги: `noindex` только где нужно, канонические URL без дублей
- Структура URL: читаемая, с ключевыми словами, без параметров где возможно

### Технический чеклист

- [ ] HTTPS везде (редирект с HTTP)
- [ ] Mobile-friendly (responsive, touch targets ≥ 44px)
- [ ] Скорость загрузки: LCP < 2.5s, FID < 100ms, CLS < 0.1
- [ ] Сжатие (gzip/brotli), кэширование, CDN
- [ ] Нет битых ссылок (404)
- [ ] Редиректы: 301 для постоянных, без цепочек
- [ ] URL без дублей (один URL = один канонический)

### On-page чеклист

- [ ] Title tag: 50-60 символов, ключевое слово в начале
- [ ] Meta description: 140-160 символов, CTA
- [ ] H1: один, с ключевым словом
- [ ] H2-H4: иерархия без пропусков
- [ ] Alt-text для изображений
- [ ] URL slug: читаемый, с ключевым словом
- [ ] Внутренние ссылки: 2-5 релевантных на страницу
- [ ] Внешние ссылки: на авторитетные источники
- [ ] Изображения сжаты (WebP), указаны размеры

### Контент для SEO

- Минимум 600 слов для информационных страниц
- Уникальный контент (не копипаста)
- E-E-A-T: опыт, экспертность, авторитетность, доверие
- Структура: сканируемая (списки, таблицы, подзаголовки)
- Обновляемость: свежие данные, актуальные даты

## 3. AEO — Answer Engine Optimization

### Как работают AI-поисковики

| Платформа | Механика | Выбор источников |
|-----------|---------|-----------------|
| **Google AI Overviews** | Суммаризация top-ranking страниц | Сильная корреляция с обычным ранжированием |
| **ChatGPT (search)** | Поиск по вебу + цитирование | Шире, чем top-10 — структура контента важна |
| **Perplexity** | Всегда цитирует с ссылками | Авторитетность + свежесть + структура |

**Ключевое отличие от SEO:** в AI-поиске страница может быть процитирована даже с 2-3 страницы выдачи — AI выбирает источники по качеству контента и структуре, а не только по позиции.

### C-SAFE Framework

Фреймворк для создания контента, который AI будет цитировать:

| Буква | Принцип | Что делать |
|-------|---------|-----------|
| **C** | **Citeable** | Данные, статистика, цифры — то, на что можно сослаться |
| **S** | **Structured** | Чёткая структура: H2-H4, списки, таблицы — AI любит извлекать |
| **A** | **Authoritative** | Авторство, источники, внешние ссылки на авторитетные ресурсы |
| **F** | **Fresh** | Дата публикации, регулярные обновления, актуальность |
| **E** | **Exhaustive** | Полнота: AI выберет самый полный ответ, не самый короткий |

### Применение C-SAFE

**Citeable (цитируемое):**
- Добавляй в текст конкретные цифры и статистику
- Используй формат «По данным [источник], ...»
- Создавай сравнительные таблицы — AI обожает их извлекать
- Делай выводы чёткими и извлекаемыми

**Structured (структурированное):**
- H2 — смысловые блоки, H3 — подблоки
- Каждый H2 — законченная мысль (AI может взять один блок)
- Списки > абзацы для перечислений
- Таблицы для сравнений
- Ключевые выводы в начале и конце

**Authoritative (авторитетное):**
- Указывай автора (имя, роль, экспертиза)
- Ссылайся на первоисточники (не на пересказы)
- Добавляй блок «Об авторе» / «О проекте»
- Используй внешние ссылки на .edu, .gov, Wikipedia

**Fresh (свежее):**
- Дата публикации и дата обновления видны
- Обновляй контент минимум раз в 6 месяцев
- Указывай версии, годы, актуальные цифры
- Убирай устаревшие данные

**Exhaustive (исчерпывающее):**
- Покрывай тему полностью, не оставляй пробелов
- Добавляй FAQ-секцию в конце
- Отвечай на смежные вопросы
- «Если читатель спросит X — ответ уже здесь»

### Проверка AEO-видимости

Проверить вручную (не через инструменты):
1. Открыть ChatGPT/Perplexity
2. Ввести целевые запросы
3. Посмотреть: цитируют ли твой сайт?
4. Если нет — кого цитируют вместо? Чем их контент лучше?

## 4. GEO — Generative Engine Optimization

### Как работают генеративные движки

| Платформа | Источник знаний | Как попасть |
|-----------|----------------|-------------|
| **Claude** | Training data + Brave Search | Качественный контент, indexed, linked |
| **Gemini** | Google Index + Knowledge Graph | Стандартный SEO + schema markup |
| **Copilot** | Bing Index | Стандартный SEO + авторитетность |

**Принцип GEO:** если ты хорошо делаешь SEO и AEO — GEO получается автоматически. Генеративные движки используют те же источники, но извлекают знания, а не цитируют.

### Что помогает в GEO

- **Knowledge Graph:** schema markup Organization/Person — Gemini подхватывает
- **Wikipedia:** наличие статьи → попадание в training data
- **Цитируемость:** чем больше тебя цитируют другие, тем выше шанс попасть в retrieval
- **Контент-хабы:** кластеры страниц вокруг одной темы → AI видит глубину экспертизы

## 5. Schema Markup (JSON-LD)

Структурированные данные помогают всем трём слоям: SEO (rich snippets), AEO (AI извлекает факты), GEO (Knowledge Graph).

### Базовые типы

| Тип | Где использовать | Минимальные поля |
|-----|-----------------|-----------------|
| `Organization` | Главная, About | `name`, `url`, `logo` |
| `WebSite` | Главная | `name`, `url`, `potentialAction` (SearchAction) |
| `Article` | Блог-посты | `headline`, `image`, `datePublished`, `author` |
| `Product` | Карточки товаров | `name`, `image`, `offers` (price, currency) |
| `FAQPage` | FAQ-страницы | `mainEntity` (Q&A массив) |
| `BreadcrumbList` | Все страницы | `itemListElement` |
| `Person` | Об авторе, команда | `name`, `url` |
| `HowTo` | Инструкции/гайды | `name`, `step` (массив шагов) |

### Пример: Organization

```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Сайтолог",
  "url": "https://siteolog.ru",
  "logo": "https://siteolog.ru/logo.png",
  "description": "AI-ассистент для создания и поддержки сайтов",
  "sameAs": [
    "https://t.me/siteolog",
    "https://github.com/siteolog"
  ]
}
```

### Пример: Article

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Заголовок статьи",
  "image": "https://example.com/image.jpg",
  "datePublished": "2026-05-09",
  "dateModified": "2026-05-09",
  "author": {
    "@type": "Person",
    "name": "Имя Автора"
  },
  "publisher": {
    "@type": "Organization",
    "name": "Сайтолог"
  }
}
```

### Правила schema

- **Точность:** размечай только то, что реально есть на странице
- **Формат:** JSON-LD в `<head>` или конце `<body>`
- **Валидация:** проверять через Google Rich Results Test перед деплоем
- **Не спамить:** не размечать невидимый контент

## 6. Site Architecture (информационная архитектура)

### Принципы

- **Важные страницы — в 3 клика от главной** (плоская иерархия)
- **Логичная структура:** главная → разделы → подразделы → страницы
- **URL — читаемые:** `/blog/slug`, а не `/index.php?id=123`
- **Внутренние ссылки:** каждая важная страница ссылается на 2-5 смежных

### Типовые структуры

**SaaS / Продукт:**
```
Главная
├── Возможности
│   ├── Фича 1
│   └── Фича 2
├── Цены
├── Блог
│   ├── Категория 1
│   └── Категория 2
├── Документация
└── О проекте / Контакты
```

**Блог / Контент:**
```
Главная
├── Блог
│   ├── Категория 1
│   │   ├── Статья 1
│   │   └── Статья 2
│   └── Категория 2
├── Об авторе
└── Контакты
```

**E-commerce:**
```
Главная
├── Каталог
│   ├── Категория 1
│   │   ├── Подкатегория
│   │   └── Продукт
│   └── Категория 2
├── Корзина
├── Блог
└── О магазине
```

### Внутренние ссылки (internal linking)

- **Хлебные крошки:** на всех страницах (schema BreadcrumbList)
- **Связанные статьи:** в конце каждого поста (3-5 ссылок)
- **Topic clusters:** pillar-страница → кластер из 5-15 подстраниц
- **Анкоры:** осмысленный текст, не «нажмите здесь»

### Topic Cluster (пример)

```
Pillar: «Создание сайта с AI»
├── «Как выбрать AI-ассистента для сайта»
├── «SSG vs SSR: что выбрать для лендинга»
├── «Headless WordPress: гайд по настройке»
├── «5 ошибок при запуске сайта»
└── «SEO для сайта на AI: пошаговый гайд»
```

## 7. Content Strategy для XEO

### Topic Clusters вместо одиночных страниц

**Плохо:** одиночные посты на разрозненные темы.
**Хорошо:** pillar-страница + 5-15 подстраниц, связанных перекрёстными ссылками.

### Приоритезация тем

| Критерий | Вес | Как оценить |
|----------|-----|-------------|
| Объём поиска | Высокий | Частотность ключевого слова |
| Близость к продукту | Высокий | Насколько тема ведёт к конверсии |
| Сложность конкуренции | Средний | Кто уже ранжируется по теме |
| Возможность кластеризации | Средний | Можно ли сделать pillar + кластер |

### Типы контента для XEO

| Тип | SEO | AEO | GEO |
|-----|:---:|:---:|:---:|
| Статья-гайд (how-to) | ✅ | ✅ | ✅ |
| Сравнение / обзор | ✅ | ✅ | ✅ |
| Чеклист | ✅ | ✅ | — |
| FAQ-страница | ✅ | ✅✅ | ✅ |
| Глоссарий терминов | ✅ | ✅ | ✅✅ |
| Кейс с метриками | ✅ | ✅✅ | — |
| Статистика / исследование | ✅✅ | ✅✅ | ✅✅ |
| Интерактивный инструмент | ✅ | — | — |

- ✅ = хорошо
- ✅✅ = отлично (платформа любит этот формат)

## 8. XEO Workflow

```
Задача на поисковую оптимизацию
│
├─ 1. АУДИТ (что сейчас?)
│   ├─ Индексация: robots.txt, sitemap, meta-теги
│   ├─ Технический: скорость, mobile, Core Web Vitals
│   ├─ On-page: title, description, H1-H4, alt, links
│   └─ AI-видимость: проверка в ChatGPT, Perplexity, AI Overviews
│
├─ 2. АРХИТЕКТУРА (как организовать?)
│   ├─ Иерархия страниц (site-architecture)
│   ├─ Topic clusters
│   └─ Внутренние ссылки
│
├─ 3. КОНТЕНТ (что писать?)
│   ├─ Выбор тем и форматов (через content-strategy)
│   ├─ Создание по C-SAFE фреймворку
│   └─ Schema markup (JSON-LD)
│
├─ 4. РЕАЛИЗАЦИЯ (как сделать?)
│   ├─ content-marketing → бриф
│   ├─ content-wordpress / content-woocommerce → черновик
│   └─ humanizer → очистка AI-следов
│
└─ 5. ИЗМЕРЕНИЕ (работает ли?)
    ├─ Позиции по ключевым словам
    ├─ Трафик (GA4 / Search Console)
    └─ AI-цитирования (ручная проверка)
```

## 9. Быстрые чеклисты

### XEO Quick Audit (15 минут)

- [ ] robots.txt — не блокирует важное
- [ ] Sitemap — существует и отправлен
- [ ] Title/meta — заполнены на всех важных страницах
- [ ] H1 — один на страницу
- [ ] Mobile — страницы не требуют горизонтального скролла
- [ ] Скорость — загружается < 3 секунд
- [ ] Schema — хотя бы Organization + WebSite + Article
- [ ] Внутренние ссылки — есть на каждой странице
- [ ] C-SAFE — проверен один целевой пост
- [ ] AI-проверка — один запрос в ChatGPT/Perplexity

### Перед публикацией страницы

- [ ] Title: 50-60 символов, ключ в начале
- [ ] Meta description: 140-160 символов, CTA
- [ ] H1: один, с ключом
- [ ] H2-H4: иерархия без пропусков
- [ ] Alt-text: все изображения
- [ ] Внутренние ссылки: 2-5
- [ ] Внешние ссылки: на авторитетные источники
- [ ] Schema: Article / Product / FAQ (по типу)
- [ ] C-SAFE: citeable, structured, authoritative, fresh, exhaustive
- [ ] Дата публикации и обновления

## 10. Правила

- **XEO сначала, инструменты потом** — методология не зависит от сервисов
- **C-SAFE для всего** — каждый контент проверять по 5 критериям
- **Schema обязательно** — JSON-LD на всех важных страницах
- **Topic clusters > одиночные страницы** — не распыляться
- **Internal linking всегда** — каждая страница ссылается на 2-5 смежных
- **AI-видимость проверять вручную** — ChatGPT/Perplexity, не инструменты
- **Контент без AI-следов** — перед публикацией через humanizer
- **SEO из данных** — ключевые слова из исследования, не из головы
