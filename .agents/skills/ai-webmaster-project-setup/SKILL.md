# AI Webmaster Project Setup

> Стартовый скилл: помогает адаптировать шаблон Сайтолога под конкретный проект.
> Формат: вопросы и ответы. Последовательно собирает информацию и вносит изменения.

## Назначение

Первый скилл, который запускается при старте нового проекта. Проводит пользователя через настройку четырёх ключевых файлов:

- `AGENTS.md` — роли, стек, правила
- `DESIGN.md` — дизайн-система
- `MARKETING.md` — маркетинговый конфиг
- `.env.example` — переменные окружения (WP, API, аналитика)

На выходе — адаптированный под проект шаблон, готовый к работе.

## Процесс

Скилл задаёт вопросы по пяти секциям. Вопросы идут последовательно — ответ на каждый влияет на следующие.

После сбора ответов скилл вносит изменения в файлы: заменяет значения по умолчанию на пользовательские.

## Секция 1: Проект (AGENTS.md)

### Q1.1 — Название проекта

> Как называется проект? (по умолчанию: «Сайтолог»)

- **Ответ →** обновить `AGENTS.md#О проекте` — заменить «Сайтолог» на название
- **Ответ →** обновить `README.md` — заменить «AI Webmaster (Сайтолог)» на новое название

### Q1.2 — Описание проекта

> Короткое описание — что делает проект? В одну-две фразы.
> (по умолчанию: «AI-ассистент для создания и поддержки сайтов»)

- **Ответ →** обновить `AGENTS.md#О проекте` — заменить описание
- **Ответ →** обновить `DESIGN.md#Brand` — обновить Product
- **Ответ →** обновить `MARKETING.md#Brand Identity` — обновить Name

### Q1.3 — Компетенции / роли

> Какие компетенции нужны проекту? Можно оставить все три или выбрать подмножество.
>
> - [ ] Программист (код, API, деплой)
> - [ ] Дизайнер (UI/UX, компоненты)
> - [ ] Маркетолог (SEO, контент)

- **Ответ →** обновить `AGENTS.md` — оставить только выбранные роли в списке компетенций и в таблице «Компетенции»

### Q1.4 — Стек

> Какой технологический стек использует проект?
>
> **Frontend:** [ ] Next.js [ ] Astro [ ] React [ ] HTML/CSS
> **CMS:** [ ] WordPress [ ] Strapi [ ] Нет
> **Языки:** [ ] TypeScript [ ] PHP [ ] JavaScript
> **Прочее:** [ ] Tailwind CSS [ ] Docker [ ] Git

- **Ответ →** обновить `AGENTS.md#Стек` — заменить на выбранный стек
- **Ответ →** обновить `site-build/SKILL.md` — скорректировать «Поддерживаемые стеки» если нужно

## Секция 4: Окружение (.env.example)

### Q5.1 — WordPress-доступ

> Нужен ли доступ к WordPress через REST API?
>
> - [ ] Да, сайт на WordPress
> - [ ] Нет, не WordPress

- **Если WordPress →** Q5.2–Q5.4, и заполнить `WP_BASE_URL`, `WP_USER`, `WP_APP_PASSWORD`
- **Если нет →** пропустить WP-секцию, закомментировать WP переменные

### Q5.2 — WP URL

> URL сайта на WordPress? Например: https://mysite.com

- **Ответ →** записать в `WP_BASE_URL`

### Q5.3 — WP пользователь

> Логин пользователя WordPress? (нужен для REST API)

- **Ответ →** записать в `WP_USER`

### Q5.4 — WP Application Password

> Application Password — создаётся в админке WP: Пользователи → Ваш профиль → Application Passwords.
> (пароль будет в .env, который НЕ коммитится)

- **Ответ →** записать в `WP_APP_PASSWORD`

### Q5.5 — AI API ключи

> Какие AI-провайдеры используются? (выбрать)
>
> - [ ] OpenAI — `OPENAI_API_KEY`
> - [ ] OpenRouter — `OPENROUTER_API_KEY`
> - [ ] Anthropic — `ANTHROPIC_API_KEY`
> - [ ] Другой: _____

- **Ответ →** раскомментировать нужные переменные в `.env.example`

### Q5.6 — Аналитика

- **Ответ →** раскомментировать нужные переменные

## Execution rules

1. **Задавать вопросы последовательно**, не все сразу
2. **Показывать дефолтное значение** в скобках — пользователь может нажать Enter чтобы оставить
3. **После каждой секции** — показывать что будет изменено и спрашивать подтверждение
4. **Не перезаписывать** то, что уже было изменено вручную (смотреть git diff)
5. **Минимальные изменения** — заменять только то, что отличается от дефолта в шаблоне
6. **Сохранять структуру** файлов — менять значения, не ломать формат
